# Flow.io Home Assistant Cards 0.3.5

## Configuration MQTT persistante

La carte accepte désormais un paramètre `mqtt_topic`, au même niveau que `entity_prefix` :

```yaml
type: custom:flowio-pool-card
entity_prefix: fio
mqtt_topic: flowio/ESP32-XXXXXX
```

`entity_prefix` identifie les entités Home Assistant. `mqtt_topic` est la racine MQTT complète `<baseTopic>/<deviceId>`, sans suffixe `/cfg/set`. Les deux valeurs sont indépendantes.

Le champ « Topic racine MQTT » est disponible dans l’éditeur visuel et enregistré dans le YAML. Aucun topic n’est détecté automatiquement. Les espaces extérieurs et slashs finaux sont retirés ; les jokers et segments vides sont refusés. Une carte sans `mqtt_topic` reste compatible.

## Menu Maintenance

La popup Maintenance lit automatiquement l’état des alarmes via le topic configuré. La saisie locale du topic est supprimée ; le topic actif est affiché en lecture seule.

Les souscriptions MQTT sont ouvertes uniquement pendant le dialogue. Elles sont fermées à sa fermeture, au changement de topic, de préfixe Home Assistant ou de connexion. Les messages provenant d’une ancienne cible sont ignorés.

Sans `mqtt_topic`, le pilotage des alarmes reste indisponible avec un message invitant à configurer la carte. Le forçage temporaire reste disponible.

## Tests

Le test e2e du forçage cible explicitement le champ « Durée (minutes) » afin d’éviter l’ambiguïté introduite par le switch « Évaluation des alarmes » dans la même popup.

## Notes de mise à jour

Ajouter `mqtt_topic` aux cartes devant piloter les alarmes Flow.io. La lecture et la publication MQTT exigent une intégration MQTT disponible et un compte administrateur Home Assistant.
